# Cell Tower Coverage Mapping and Service-Area Engine

Interactive Python GIS application for a college **Data Structures and Algorithms** case study. It maps recorded cell locations around **Chennai, Tamil Nadu**, estimates a **documented proximity score** (not measured signal), and demonstrates three structures:

1. **Zone-Mapped Column Blocks** — spatial index with per-block min/max summaries.
2. **Half-Edge / DCEL** built on a SciPy Delaunay triangulation.
3. **Roaring Bitmaps** (PyRoaring) for operator and radio filters.

The UI is a single Streamlit page: the Folium map is the main surface, with a compact control sidebar and a nearest-record panel.

## Use cases

- Click or geocode a place in Chennai and inspect the nearest *recorded* cells in the loaded dataset.
- Toggle assumed coverage circles, a red/yellow/green proximity grid, Delaunay neighbour edges, and geometric Voronoi cells.
- Explain construction, search, and filtering complexity honestly in a viva.

This is **not** a radio-planning tool. A missing record is not a real-world dead zone. A high proximity score is **not** dBm, RSSI, or RSRP.

## Architecture

```
app.py                     Streamlit + Folium dashboard
src/data_loader.py         Schema, validation, synthetic DEMO, OpenCelliD/OSM parsers

src/bitmap_filters.py      PyRoaring indexes and set algebra
src/distance.py            Haversine + UTM 44N (EPSG:32644) projections
src/signal_model.py        Configurable distance-based score 0–100
src/map_layers.py          Markers, circles, grid, Voronoi, Delaunay overlays
src/geocoding.py           Nominatim with cache and rate limit
scripts/prepare_dataset.py Dataset acquisition
scripts/benchmark.py       Timed comparisons with result equality checks
```

SciPy computes Delaunay/Voronoi **geometry**. The **DCEL linking**, **spatial index**, and **Roaring filters** are implemented in this repository.

## Dataset

Preferred authentic source: **OpenCelliD** (CC BY-SA 4.0). Downloads require `OPENCELLID_API_KEY`.

1. Copy `.env.example` to `.env` and set the token (never commit `.env`).
2. Run:

```powershell
python scripts/prepare_dataset.py
```

The script tries, in order:

1. OpenCelliD (if a token is present).
2. OpenStreetMap Overpass communication towers in the Chennai box (ODbL; genuine OSM features, **not** a complete operator inventory).
3. A **labelled synthetic DEMO** CSV (always generated).

Without a token the app still runs on synthetic points confined to the Chennai demonstration rectangle. Those points are **not** real infrastructure.

OpenCelliD `range` is documented as an *estimated* cell range in metres. `averageSignal` is deprecated and always `0`. The default model does **not** treat `range` as a calibrated coverage radius.

## DSA notes (viva)

### 1. Why zone-mapped column blocks?

Uniform lat/lon grids distort east–west distance. Towers are converted to **UTM zone 44N metres**, then dropped into **columns along X** and **blocks along Y**. Each occupied block stores `min_x, max_x, min_y, max_y` and the tower IDs inside it. That is a simple array/hash of spatial summaries — easy to draw on a board, with a correct nearest-neighbour algorithm.

### 2. How min/max summaries discard candidates

For a query point *q*, the Euclidean distance to any tower in a block is at least the distance from *q* to the block’s axis-aligned rectangle. If that lower bound is already worse than the best tower seen, the whole block is skipped. Search **must** inspect neighbouring blocks; otherwise a tower just across a block edge would be missed.

### 3–4. Why a Half-Edge / DCEL?

A list of SciPy triangles is not enough to walk “the three neighbours of this triangle” or “the star of this vertex” without rebuilding adjacency every time. Each **half-edge** stores:

- `origin` — start vertex
- `twin` — opposite directed edge (absent on the convex-hull boundary)
- `next` — next edge around the same face (cycle of 3 for triangles)
- `face` — incident triangle

`twin.twin is self` and `e.next.next.next is e` are the invariants tests check.

### 5. Roaring Bitmaps

Each tower has a stable integer `tower_id`. PyRoaring `BitMap` stores compressed sets for each radio, operator, and source. Active UI filters **intersect** those bitmaps; the resulting IDs constrain the spatial search so the map and the nearest-tower panel stay consistent.

### 6. Complexity (do not claim everything is O(log n))

| Structure | Build | Query (typical local data) | Worst case |
| --- | --- | --- | --- |
| Column blocks | Θ(n) | Inspect a neighbourhood of blocks | Θ(n) — all blocks/towers |
| DCEL from triangulation | Θ(t) on t triangles | Face walk Θ(1) for a triangle; vertex star Θ(degree) | Degenerate input: no faces |
| Roaring filter | Θ(n) | Intersect/union over selected categories | Linear in bitmap size; still Θ(n) to scan if you materialise every ID |

Expected speed-ups vs brute force are **empirical**. Benchmarks in `scripts/benchmark.py` record actual times.

### 7. Edge cases

- Empty dataset, duplicate coordinates, collinear sites, query outside the grid, range-query radius 0, missing API token, geocoder failure (fall back to map click / manual lat-lon).
- Voronoi cells are a **nearest-tower partition**, not a radio footprint.
- Infinite Voronoi rays are clipped to the Chennai rectangle.

### 8. What we implemented vs libraries

- **Us:** DCEL classes and linking, zone-mapped search with AABB pruning, Roaring filter assembly, proximity model, Streamlit/Folium UX, tests.
- **Libraries:** SciPy Delaunay/Voronoi, PyProj transforms, Shapely clips, PyRoaring container, Folium rendering, Geopy Nominatim.

## Troubleshooting

- **Map click does nothing:** wait for the Streamlit rerun; `st_folium` reports `last_clicked`.
- **Address search fails:** Nominatim may rate-limit or be unreachable. Use map click or typed coordinates. Cache lives in `.cache/geopy/`.
- **pyroaring install fails:** the filter module requires it; capture the pip error. Do not pretend Python `set` is a Roaring Bitmap.
- **OpenCelliD empty:** token missing, HTTP error, or no India MCC rows in the Chennai box — the UI must show synthetic fallback text.
- **Slow grid:** increase grid resolution (metres) or pan before enabling the overlay.

## Limitations

Proximity `score = 100 * max(0, 1 - distance / assumed_radius)`, combined by **maximum** over candidates. Assumed radii by radio are modelling knobs. No terrain, buildings, frequency, or load are modelled.
